01. Objective

The objective of this assignment is to identify and plan RESTful APIs for a To-Do List application. These APIs will help users create, view, update and delete tasks. This assignment focuses on API planning, not implementation.

06. Common HTTP Status Codes

Status Meaning Example
200 OK Success Task retrieved or updated
201 Created Resource created New task added
204 No Content Success without response body Task deleted
400 Bad Request Invalid data Missing task title
404 Not Found Resource not found Invalid task ID
500 Server Error Unexpected server issue Database failure

07. Potential Challenges

  • Validation: Prevent empty titles and invalid data.
  • Unique IDs: Generate a unique identifier on the server.
  • Data persistence: Save tasks in a database.
  • Error handling: Handle missing tasks and failed requests.
  • Frontend synchronization: Refresh the UI after changes.
  • Security: Protect user-specific tasks with authentication.
  • Network issues: Handle timeouts and connection failures.

08. How the APIs Work

The React frontend sends HTTP requests to the backend. The backend validates the request, performs the required operation in the database, and returns a response in JSON. The frontend then updates the displayed task list.

09. Conclusion

The planned APIs follow RESTful principles by using resource-based URLs, standard HTTP methods, JSON data, unique identifiers and meaningful status codes. Together, they cover the CRUD operations required for a To-Do List application.
